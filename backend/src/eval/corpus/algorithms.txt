Sorting Algorithms Study Notes

Sorting is the process of arranging elements of a list or array into a particular order, typically ascending or descending numerical or lexicographic order. Sorting is one of the most extensively studied problems in computer science because so many other algorithms, such as binary search and various graph algorithms, depend on operating over sorted data to achieve their best performance. Sorting algorithms are commonly compared using time complexity, space complexity, and stability, which refers to whether elements with equal keys retain their original relative order.

Bubble sort is one of the simplest sorting algorithms to understand and implement. It repeatedly steps through the list, compares each pair of adjacent elements, and swaps them if they are in the wrong order. This process is repeated until a full pass through the list requires no swaps, indicating the list is sorted. Bubble sort has a worst-case and average time complexity of O(n squared), making it impractical for large datasets, but its simplicity makes it a common first algorithm taught to beginners.

Selection sort works by dividing the list into a sorted portion at the front and an unsorted portion at the back. On each pass, the algorithm searches the unsorted portion for the smallest remaining element and swaps it into place at the end of the sorted portion. Like bubble sort, selection sort has a time complexity of O(n squared) in all cases, since it always scans the remaining unsorted elements regardless of how nearly sorted the list already is. Its main advantage is that it performs at most n swaps, which can matter when write operations are expensive.

Insertion sort builds a sorted list one element at a time by taking each new element and inserting it into its correct position among the previously sorted elements, shifting larger elements to the right as needed. Insertion sort performs very well on small or nearly sorted datasets, achieving close to O(n) performance in the best case, though its worst case remains O(n squared). Because of this efficiency on small inputs, many practical sorting implementations, including some versions of quicksort, switch to insertion sort once the subarrays being sorted become small enough.

Merge sort is a divide-and-conquer algorithm that recursively splits the list into halves until each sublist contains a single element, then merges those sublists back together in sorted order. The merge step compares the front elements of two sorted sublists and repeatedly takes the smaller one, producing a combined sorted sequence. Merge sort guarantees O(n log n) time complexity in the best, average, and worst cases, making it far more predictable than algorithms like quicksort, though it typically requires O(n) additional memory for the merging process, unlike simpler in-place algorithms.

Quicksort is another divide-and-conquer algorithm, but instead of splitting the list evenly, it selects a pivot element and partitions the remaining elements into two groups: those less than the pivot and those greater than the pivot. It then recursively sorts each partition. Quicksort has an average time complexity of O(n log n) and is often faster in practice than merge sort due to good cache locality and low constant factors, but its worst-case time complexity is O(n squared), which occurs when the chosen pivot repeatedly produces highly unbalanced partitions, such as when the input is already sorted and the first element is always chosen as the pivot.

Heapsort uses a data structure called a binary heap, typically a max-heap, to sort a list. The algorithm first builds a max-heap from the input data, then repeatedly removes the maximum element from the root of the heap and places it at the end of the array, shrinking the heap by one each time and restoring the heap property after each removal. Heapsort achieves a guaranteed O(n log n) time complexity in all cases and sorts in place without requiring extra memory, though it tends to have worse real-world performance than quicksort due to poor cache locality when navigating the heap's tree structure.

Counting sort is a non-comparison-based sorting algorithm that works well when the range of possible input values, often called the key range, is small relative to the number of elements being sorted. It counts the number of occurrences of each distinct value, then uses those counts to determine the correct position of each element in the output array. Counting sort achieves O(n plus k) time complexity, where k is the range of input values, making it faster than comparison-based sorts like merge sort or quicksort for the specific case of small integer ranges, but it becomes impractical when k is very large.

Radix sort is another non-comparison-based algorithm that sorts integers by processing individual digits, starting from either the least significant digit or the most significant digit, and using a stable subroutine such as counting sort at each digit position. Because it processes numbers digit by digit rather than comparing them directly, radix sort can achieve linear O(nk) time complexity, where k is the number of digits, making it especially effective for sorting large sets of fixed-length integers or strings.

The theoretical lower bound for comparison-based sorting algorithms is O(n log n), which can be proven using a decision tree argument: any comparison sort can be modeled as a binary decision tree where each leaf represents one possible ordering of the input, and since there are n factorial possible orderings, the tree must have a height of at least log base 2 of n factorial, which simplifies to O(n log n) by Stirling's approximation. This is why algorithms like merge sort and heapsort, which achieve O(n log n), are considered asymptotically optimal among comparison-based approaches.

Stability in sorting refers to whether elements that compare as equal retain their original relative order after sorting. Merge sort, insertion sort, and bubble sort are naturally stable, while standard implementations of quicksort and heapsort are not stable because their swapping and partitioning steps can reorder equal elements. Stability matters in practical applications such as sorting a list of students first by grade and then by name, where you want students with the same grade to remain in their original alphabetical order rather than being shuffled arbitrarily.

In practice, most standard library sort implementations use hybrid algorithms rather than a single pure technique. Timsort, used by Python and Java, combines merge sort and insertion sort, taking advantage of existing ordered runs within real-world data to reduce the number of comparisons needed. Introsort, used in many C++ standard library implementations, begins with quicksort for speed but switches to heapsort if the recursion depth becomes too large, guarding against quicksort's worst-case O(n squared) behavior on adversarial or already-sorted inputs.
